| 한지수 | A. 정류장 목록 | 강대운(백엔드), 곽도윤(LLM) | 11/10 |
| 한지수 | B. 통화 대본 20개와 정답지 | 곽도윤(LLM) | 11/13 |

| 김채영 | D. 상담원 화면 설계 | 지민준(프론트) | 11/10 |

## 한지수

### A. 정류장 목록 → `data/정류장.csv` (완료)

시연 권역은 대구 수성구 **범물동주거지역 17곳**이다. 출처·별칭 근거·정답 규칙은 `docs/기획/한지수/말로부르는버스_시연데이터.xlsx`에 정리했다. 아래는 작성 방법이다.

AI가 "어디서 탈지"를 고를 때 쓰는 목록이다. AI는 이 목록에 있는 정류장만 고를 수 있다.

1. 공공데이터포털에서 「대구교통공사_DRT 정류장 위치 정보」 파일을 내려받는다. (https://www.data.go.kr/dcat/metadata/15152401)
2. 시연할 동네 하나를 고른다. 주거지역인 **수성구 범물동**이나 **북구 연암서당골**을 우선 본다. (회의에서 확정)
3. 그 동네 정류장 20곳 안팎을 `data/정류장.csv`에 옮긴다. 이름과 위도·경도는 원본 그대로 쓴다.
4. **별칭** 칸에 어르신이 실제로 부를 법한 이름을 적는다. 여러 개면 `|`로 구분한다.

| 열 | 쓰는 법 | 예시 |
|---|---|---|
| 정류장ID | S01부터 차례로 | S01 |
| 정류장명 | 원본 그대로 | 범물동 행정복지센터 |
| 위도 / 경도 | 원본 그대로 | (원본 값) |
| 별칭 | 생활 지명, `\|`로 구분 | 동사무소\|주민센터\|동네 사무소 |
| 메모 | 헷갈릴 만한 점 | 근처에 같은 이름의 다른 정류장 있음 |

별칭 쓰는 요령:
- 지도에서 정류장 주변 건물(병원, 시장, 아파트, 학교)을 보고 "○○ 앞", "○○ 병원"처럼 적는다.
- **일부러 헷갈리는 경우를 2~3개 남긴다.** 예: "시장"이라고 부를 만한 정류장이 2곳. 이게 '확인 필요' 시연에 쓰인다.
- 별칭은 팀이 만든 예시라고 README에 적혀 있으니, 정확하지 않아도 괜찮다.

### B. 통화 대본 20개와 정답지 → `test/대본_정답지.csv` (완료)

AI를 시험하는 **문제지(대본)와 답안지(정답)** 다. 한 줄에 대본 하나와 그 정답을 같이 적는다. A의 정류장 이름을 그대로 쓰므로 A를 먼저 끝낸다.

회의 결정(2026-11-09)에 따라 목적은 "이동수단 예약" 고정, 인원·왕복은 채점하지 않는다. 대본 20개는 모두 예약이다.

| 유형 | 개수 | 시험하는 것 |
|---|---|---|
| 쉬운 예약 | 6 | 정식 이름, 오늘·내일·모레 날짜 계산 |
| 별칭으로 말함 | 4 | "하늘채", "백화점", "동사무소 건너편" → 정류장 하나 |
| 같은 이름 정류장 | 2 | "동사무소"(2곳), "범물동 행정복지센터"(3곳) → 후보 전부 + 확인 필요 |
| 오전·오후를 말 안 함 | 2 | 제안값 + 시간 확인 필요 |
| 목록에 없는 곳 | 2 | 지어내지 않고 비움 + 확인 필요 |
| 말을 바꿈 | 2 | 마지막 값 사용 (기능규칙서 7.3) |
| 관계없는 장소·숫자 | 2 | 지금 있는 곳·나이를 예약 정보로 쓰지 않음 (기능규칙서 7.1, 7.2) |

정답지 열: `번호, 유형, 접수일시, 대본, 출발, 도착, 날짜, 시간, 확인필요`

- 대본: 통화 전체를 한 칸에. 말 바뀔 때 ` / `, 앞에 `상담원:` `어르신:`
- 출발·도착: 정류장ID. `S01|S12`는 확정 없이 그 후보가 모두 떠야 정답. 빈칸은 후보 없이 비어야 정답
- 날짜 `YYYY-MM-DD`, 시간 `HH:MM`(24시간)
- 확인필요: 출발·도착·날짜·시간 중 '확인 필요'가 떠야 하는 칸, `|`로 구분

**프롬프트 예시 대본** `data/프롬프트예시_대본.csv` (10개): LLM 프롬프트 예시용. 채점용 20개와 문장이 겹치지 않고 접수일도 다르다. **채점용 20개는 프롬프트에 넣지 않는다.**

변경·취소·문의 대본 4개는 엑셀의 '추가기능_대본' 시트에만 있다 (채점 제외).

주의: 실제 사람 이름·전화번호·실제 녹음은 넣지 않는다.

### C. 채점 결과표 (11/15~16)

대본 20개를 `/extract`에 넣고 정답과 비교한다. 출발·도착·날짜·시간·확인필요 5칸을 O/X로 본다. 백엔드 채점 테스트(`./gradlew grade`)가 결과표를 만들고, 한지수가 틀린 대본의 원인을 한 줄씩 정리한다. 목표에 못 미쳐도 그대로 보고한다.

## 김채영

### D. 상담원 화면 설계 → `docs/기획/김채영/화면설계/`

상담원이 통화하면서 보는 화면을 그린다. 손그림 사진, PPT, Figma 다 괜찮다. 예쁠 필요는 없고 **어디에 무엇이 있는지**만 보이면 된다. 참고: `prototype/agent.html`을 크롬으로 열어 보기.

그릴 화면 2개:
1. **통화 보조 화면**
   - 왼쪽: 통화 내용이 한 줄씩 쌓이는 칸
   - 오른쪽: 예약 양식 (목적, 출발, 도착, 날짜, 시간, 인원)
   - 출발·도착 칸: 정류장 후보 목록에서 고르기
   - '확인 필요' 표시가 어떻게 보이는지 (색, 글자)
   - **확정** 버튼
2. **확정 결과 화면**: 확정된 예약이 어떻게 보이는지

각 그림 옆에 동작을 적는다. 예: "확인 필요 칸을 모두 고르기 전에는 확정 버튼이 눌리지 않는다."

### E. 기능 규칙서 → `docs/기획/김채영/기능규칙.md`

화면이 **어떤 상황에서 어떻게 동작하는지** 정하는 문서다. 개발자가 헷갈릴 때 이 문서를 보고 판단한다.

1. **예약 항목 정의**: 칸마다 이름, 형식, 비었을 때 처리
   - 예: 날짜 = YYYY-MM-DD, "내일"은 접수일 다음 날, 말하지 않으면 '확인 필요'
2. **'확인 필요' 규칙**: 언제 뜨고 상담원이 무엇을 하는지
   - 시작점은 `서비스소개.md` 6장의 "확인 필요 기준" 표
   - 빠진 경우를 더 찾는다. 예: 인원을 말하지 않으면? 출발과 도착이 같으면?
3. **상담원 확정 흐름**: 고치기 → 확정 → 저장 순서, 확정 뒤에 고칠 수 있는지
4. **저장 항목**: 확정할 때 남길 것. `서비스소개.md` 9장의 JSON 초안을 기준으로, 형식은 강대운(백엔드)과 맞춘다.

### F. 현장 확인 전화 → `docs/기획/김채영/현장확인.md`

지금 근거는 문서(국토부 가이드라인)뿐이다. 실제 DRT 콜센터의 이야기가 들어가면 발표와 결과 보고가 훨씬 설득력 있어진다.

1. 대구교통공사 DRT 콜센터(또는 시연 권역 운영 기관)에 전화한다. 학생 프로젝트라고 먼저 밝힌다.
2. 질문은 세 가지만 한다.
   - 전화 예약을 받을 때 가장 오래 걸리거나 헷갈리는 부분은 무엇인가요?
   - 하루 전화 예약은 몇 건 정도인가요?
   - 어르신들이 정류장 이름 대신 많이 쓰는 표현이 있나요?
3. 날짜, 기관명, 답변 요지를 `docs/기획/김채영/현장확인.md`에 적는다. 상담원 이름·연락처는 적지 않는다.
4. 세 번째 답은 한지수에게 바로 공유한다. 정류장 별칭(A)에 쓴다.

통화가 안 되면 안 된 대로 적는다. 이 결과물이 없어도 개발은 진행된다.
