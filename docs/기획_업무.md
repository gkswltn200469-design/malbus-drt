## 한지수

### A. 정류장 목록 → `data/정류장.csv`

AI가 "어디서 탈지"를 고를 때 쓰는 목록이다. AI는 이 목록에 있는 정류장만 고를 수 있다.

1. 공공데이터포털에서 「대구교통공사_DRT 정류장 위치 정보」 파일을 내려받는다. (https://www.data.go.kr/dcat/metadata/15152401)
2. 시연할 동네 하나를 고른다. 주거지역인 **수성구 범물동**이나 **북구 연암서당골**을 우선 본다. (회의에서 확정)
3. 그 동네 정류장 20곳 안팎을 `data/정류장.csv`에 옮긴다. 이름과 위도·경도는 원본 그대로 쓴다.
4. **별칭** 칸에 어르신이 실제로 부를 법한 이름을 적는다. 여러 개면 `|`로 구분한다.

| 열 | 쓰는 법 | 예시 |
|---|---|---|
| 정류장ID | S01부터 차례로 | S01 |
| 정류장명 | 원본 그대로 | 범물동 행정복지센터 |
| 위도 / 경도 | 원본 그대로 | (원본 값) |
| 별칭 | 생활 지명, `\|`로 구분 | 동사무소\|주민센터\|동네 사무소 |
| 메모 | 헷갈릴 만한 점 | 근처에 같은 이름의 다른 정류장 있음 |

별칭 쓰는 요령:
- 지도에서 정류장 주변 건물(병원, 시장, 아파트, 학교)을 보고 "○○ 앞", "○○ 병원"처럼 적는다.
- **일부러 헷갈리는 경우를 2~3개 남긴다.** 예: "시장"이라고 부를 만한 정류장이 2곳. 이게 '확인 필요' 시연에 쓰인다.
- 별칭은 팀이 만든 예시라고 README에 적혀 있으니, 정확하지 않아도 괜찮다.

### B. 통화 대본 20개와 정답지 → `test/대본_정답지.csv`

AI를 시험하는 **문제지(대본)와 답안지(정답)** 다. 한 줄에 대본 하나와 그 정답을 같이 적는다. A의 정류장 이름을 그대로 쓰므로 A를 먼저 끝낸다.

대본 20개의 구성:

| 유형 | 개수 | 대본 예시 (어르신 말) | 정답에서 볼 점 |
|---|---|---|---|
| 쉬운 예약 | 6 | 내일 오전 9시에 범물동 행정복지센터에서 ○○병원 가요 | 모두 확인 완료 |
| 별칭으로 말함 | 4 | 내일 아침 아홉 시에 동사무소 앞에서 병원 가요 | 별칭 → 정류장 이름 |
| 같은 별칭 정류장이 2곳 | 2 | 모레 시장 앞에서 타요 | 출발 '확인 필요' |
| 오전·오후를 말 안 함 | 2 | 내일 세 시에 회관에서요 | 시간 '확인 필요' |
| 목록에 없는 곳 | 2 | 내일 큰딸네 집 앞에서 타요 | 지어내지 않고 '확인 필요' |
| 예약 변경 | 2 | 내일 9시 예약한 거 10시로 바꿔 줘요 | 목적 = 변경 |
| 예약 취소 | 1 | 내일 예약 취소할게요 | 목적 = 취소 |
| 문의 | 1 | 일요일에도 버스 다녀요? | 목적 = 문의 |

정답지 열:

| 열 | 쓰는 법 | 예시 |
|---|---|---|
| 번호 | 1~20 | 1 |
| 유형 | 위 표의 유형 | 별칭으로 말함 |
| 접수일시 | 전화 받은 때. "내일"을 날짜로 바꾸는 기준 | 2026-11-17 14:00 |
| 대본 | 통화 전체를 한 칸에. 말 바뀔 때 `/`, 앞에 `상담원:` `어르신:` | 상담원: 네 말씀하세요 / 어르신: 내일 아침 아홉 시에 동사무소 앞에서 병원 가요 |
| 목적 | 예약 / 변경 / 취소 / 문의 | 예약 |
| 출발 | 정류장ID (없으면 비움) | S01 |
| 도착 | 정류장ID (없으면 비움) | S07 |
| 날짜 | YYYY-MM-DD | 2026-11-18 |
| 시간 | HH:MM, 24시간 | 09:00 |
| 인원 | 숫자 | 1 |
| 확인필요 | '확인 필요'가 떠야 하는 칸, `\|`로 구분 (없으면 비움) | 출발\|시간 |

주의: 실제 사람 이름·전화번호·실제 녹음은 넣지 않는다.

### C. 채점 결과표 → `test/채점결과.md` (11/15~16)

개발이 끝나면 대본 20개를 화면에 넣어 보고 AI 답을 정답과 비교한다.

| 번호 | 목적 | 출발 | 도착 | 날짜 | 시간 | 인원 | 확인필요 표시 | 메모 |
|---|---|---|---|---|---|---|---|---|
| 1 | O | O | X | O | O | O | O | 도착을 S06으로 고름 |

맨 아래에 정리한다.
- 항목별 정답률 (예: 출발 18/20)
- 20개 모두 맞은 대본 수
- 틀린 대본의 원인 한 줄씩. 목표에 못 미쳐도 그대로 쓴다.

## 김채영

### D. 상담원 화면 설계 → `docs/화면설계/`

상담원이 통화하면서 보는 화면을 그린다. 손그림 사진, PPT, Figma 다 괜찮다. 예쁠 필요는 없고 **어디에 무엇이 있는지**만 보이면 된다. 참고: `prototype/agent.html`을 크롬으로 열어 보기.

그릴 화면 2개:
1. **통화 보조 화면**
   - 왼쪽: 통화 내용이 한 줄씩 쌓이는 칸
   - 오른쪽: 예약 양식 (목적, 출발, 도착, 날짜, 시간, 인원)
   - 출발·도착 칸: 정류장 후보 목록에서 고르기
   - '확인 필요' 표시가 어떻게 보이는지 (색, 글자)
   - **확정** 버튼
2. **확정 결과 화면**: 확정된 예약이 어떻게 보이는지

각 그림 옆에 동작을 적는다. 예: "확인 필요 칸을 모두 고르기 전에는 확정 버튼이 눌리지 않는다."

### E. 기능 규칙서 → `docs/기능규칙.md`

화면이 **어떤 상황에서 어떻게 동작하는지** 정하는 문서다. 개발자가 헷갈릴 때 이 문서를 보고 판단한다.

1. **예약 항목 정의**: 칸마다 이름, 형식, 비었을 때 처리
   - 예: 날짜 = YYYY-MM-DD, "내일"은 접수일 다음 날, 말하지 않으면 '확인 필요'
2. **'확인 필요' 규칙**: 언제 뜨고 상담원이 무엇을 하는지
   - 시작점은 `서비스소개.md` 6장의 "확인 필요 기준" 표
   - 빠진 경우를 더 찾는다. 예: 인원을 말하지 않으면? 출발과 도착이 같으면?
3. **상담원 확정 흐름**: 고치기 → 확정 → 저장 순서, 확정 뒤에 고칠 수 있는지
4. **저장 항목**: 확정할 때 남길 것. `서비스소개.md` 9장의 JSON 초안을 기준으로, 형식은 강대운(백엔드)과 맞춘다.

### F. 회의록과 일정 확인 → `docs/회의록/`

- 회의마다 날짜, 정한 것, 할 일(누가·언제까지)을 짧게 남긴다.
- 11/14 중간 점검 전에 각자 결과물이 올라왔는지 확인한다.
